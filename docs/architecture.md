# 구조와 다음 단계

## 데이터 흐름

1. `__main__.py`: 필수 MD 확인 → 선택 문서 읽기 → 공통 조사 프롬프트 구성.
2. Codex/Claude CLI: 웹 조사 → `schema.py`의 동일 JSON 규격으로 응답.
3. `core.py`: 응답 검증 → URL 정규화 → 이전 상태 병합 → 마감일 정렬 → Markdown 생성.
4. 사용자는 지원표의 상태·메모와 개별 공고의 내 메모 영역을 편집.
5. 재실행은 위 영역을 보존하고 미재확인 공고를 별도로 유지.

Python 표준 라이브러리만 사용한다. 저장소를 복제해 실행하는 방식이며 패키지 배포는 아직 없다.
기본 모델은 사용자의 각 CLI 설정을 따른다. 프로필은 stdin으로 전달한다.
AI에 보고서 편집을 맡기지 않고 검증된 결과만 렌더러가 쓴다.

## 다음 단계

- 실제 공개 채용 사이트를 이용한 두 제공자별 통합 검증
- 파일 업로드와 실행 버튼이 있는 로컬 화면
- 필수 조건 추출 결과를 사용자가 검토하는 단계
- 주당 지원 가능량·예상 준비 시간에 따른 일정 배분
- URL이 바뀌어도 공고 식별자를 이용해 기록을 연결하는 ATS별 정규화
- 더 엄격한 근거 확인과 신뢰할 수 있는 사이트별 수집기
- 실행 취소, 진행률, 동시 실행 잠금, 여러 파일을 함께 교체하는 트랜잭션
- 영어 문서·다국어 결과

## 알려진 제약

각 파일은 임시 파일로 쓰고 교체한다. 여러 파일 전체의 트랜잭션은 아니므로 디스크 오류나
프로세스 강제 종료 시 일부 결과만 갱신될 수 있다. 하나의 출력 폴더에서 동시 실행하지 않는다.
동일 URL의 추적 매개변수 중복은 검증하지만, 서로 다른 플랫폼의 동일 공고 통합은 AI가 수행한다.
주간 지원 한도는 자동 계산하지 않는다. 시간대는 원문 설명으로 보존하고 날짜 단위로 정렬한다.
