# 첨삭과 제한된 재작성 후속 계획

[English](../en/tailoring-followup.md) · **한국어**

상태: 후속 제안이며 v0.2에는 구현하지 않는다. [조사 규격](research-contract.md)과
[품질 평가](quality-evaluation.md)의 근거 구조를 기반으로 한다. 실제 이력서 수정과 지원서 제출은
도구 범위에서 제외한다. 아래 항목은 각각 별도로 구현한다.

## 1. 선택 공고 규격과 안정적인 참조

`tailor <research> --job <job-id> --inputs <directory> --resume <optional-file> --agent <provider>`를
추가한다. 제공자 호출 전에 URL 정규화 기반 ID로 기존 공고 하나를 확정한다. v1 조사라면 새 구조화
근거를 요구하거나 검토용 개요만 제공한다. 없는 참조를 만들어 내지 않는다.

공고 ID·정규화된 요구사항 문구·중요도로 요구사항 ID를 만든다. 근거가 바뀌면 종속 제안을 무효화할 수
있도록 각 ID에 내용 리비전을 둔다. 중복 요구사항 ID는 거부한다. 제안 ID는 공고 ID·연결 요구사항 ID·
원문 위치·제안 종류로 만든다. 원문·제안문·근거 참조의 별도 리비전 해시를 저장한다.
이 해시는 비공개 첨삭 상태에 속하며 조사 지침 해시에 포함하지 않는다.

명시적으로 선택한 이력서와 지정 입력 폴더의 문서만 읽는다. 읽기 전에 경로를 해석하고 폴더를 벗어나는
경로·심볼릭 링크를 거부한다. 모델이 반환한 파일명을 따라 읽지 않는다. 근거는 파일명·섹션·정확한 인용·
등장 순서 또는 줄 범위를 가리킨다. 원문 문장이 없거나 중복되어 불명확하면 `original=null`인 개요를
제공하며 원문을 꾸며 내서 수정한 것처럼 표시하지 않는다.

## 2. 제안과 검토 상태

`output/jobs/<job-id>-tailoring.json`과 `.md`에 원문·제안문·요구사항 ID·근거 참조·검증 메시지·
`accepted`/`rejected`/`needs-review` 사용자 상태를 쓴다. 이력서·조사 결과·지원표·선택하지 않은 공고는
수정하지 않는다. 검증 결과와 사용자 상태는 구분한다. 검증 통과가 자동 승인을 뜻하지 않는다.

제안 ID와 리비전, 연결 요구사항, 인용 원문이 모두 같을 때만 사용자 상태를 유지한다. 바뀌었다면
`needs-review`로 되돌리고 이유를 표시한다. 이전 리비전은 검토용으로 보관한다. 모든 출력을 준비한 뒤
교체하고 기존 마커 방식으로 사용자 메모를 보존한다.

## 3. 재작성 전 검증

깨진 참조·필수 필드 누락·정확한 원문과 맞지 않는 주장은 거부한다. 제안의 이름·숫자·기간·기술·책임·
길이 증가·새 정량 표현을 확인하고 인용 입력에 근거가 없으면 검토 대상으로 표시한다. 단순 어휘 검사로
의미상의 진위를 증명하지 않는다. 제안의 구체적 주장마다 근거를 연결하고 미해결 주장과 질문을 Markdown에 보여 준다.

## 4. 제한된 수정 요청

구조 또는 근거 검증 실패일 때만 수정한다. 기본 재작성은 1회, 0회도 허용하고 최대 2회로 제한한다.
최초 호출과 모든 수정에 하나의 단조 시계 기준 제한 시간을 적용하고 각 하위 프로세스에는 남은 시간만
전달한다. 수정 요청은 검증 오류와 필요한 최소 근거만 포함한다. 모델의 자기 점수를 승인 기준으로 쓰지
않으며 제공자 사용량 정보 없이 토큰 비용 상한을 보장하지 않는다.

반환된 응답은 파싱 전에 원문으로 저장하고 파싱 가능하면 JSON도 저장한다. 횟수나 시간이 소진되면
마지막 결과와 오류를 `needs-review`로 보존한다. 잘못된 JSON은 확인할 수 있는 원문 자료로 남기며
검증에 성공한 제안으로 취급하지 않는다. 생성 실패로 기존 승인 상태를 바꾸지 않는다.

## 완료 검증

가상 오프라인 사례와 모의 제공자로 선택 공고 격리·중복 ID·원문 누락과 중복·근거 없는 주장·원문 변경·
승인 무효화·변경 없는 상태 유지·잘못된 JSON·재시도 상한·공통 제한 시간을 검사한다. 원래 입력·조사·
지원표의 바이트를 저장해 변경되지 않았음을 확인한다. 구현 항목마다 전체 테스트를 실행하고 두 언어를
함께 관리한다. 실제 제공자 평가는 명시적인 별도 명령으로 유지한다. v0.2에는 첨삭 CLI가 없다.
